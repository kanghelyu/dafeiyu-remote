# MVP 定义与验收标准（v0.1）

目标：**Windows ↔ Windows 远程桌面可用**，局域网直连，1080p60 / H.264，键鼠、剪贴板文本、文件传输基础版；在此之上逐步加 NAT/relay、mac/Linux、虚拟屏、音频。

## 1. 范围（P0）

| 模块 | MVP 要求 | 不做 |
|---|---|---|
| 会话 | 手动输入 IP/端口 + 6 位临时码；握手/权限/断开/重连 | 账号体系、设备列表 |
| 视频 | DXGI 采集 → H.264（优先 NVENC/AMF/QSV，回退 OpenH264 软编）→ QUIC DATAGRAM + 分片 → 解码渲染；60fps、码率自适应 1–20Mbps | AV1/H.265、HDR、4:4:4、窗口串流 |
| 输入 | 绝对/相对鼠标、扫描码+Unicode 双通道、快捷键四态分流、Ctrl+Alt+Del 转发 | 手柄、触摸、虚拟 HID |
| 剪贴板 | 文本 + PNG 图片双向，清单→拉块，自激抑制 | HTML/RTF/文件剪贴板 |
| 文件 | 拖拽/粘贴上传、块传输、断点续传、进度、覆盖/跳过策略 | 目录同步、拖拽下载目录树 |
| 安全 | TLS1.3 + 设备身份校验（可关闭用于自签测试）、临时密码、连接日志 | 企业策略、TOTP |
| UI | 连接页、全屏/窗口/迷你窗、悬浮工具栏、网络状态、错误页/重试 | 皮肤、插件、多语言（先中/英） |

## 2. 验收脚本（每次迭代必须全绿）

1. **协议自测**：`cargo run -p dfy-cli -- selftest` → `SELFTEST OK`（本机 QUIC 握手 + 视频/输入 DATAGRAM）。
2. **采集自测**：`cargo run -p dfy-capture --example capture -- --frames 10 --out .tmp/preview.png` → 帧数=10、尺寸=显示器分辨率、PNG 可视。
3. **编码自测**（M1 起）：`cargo run -p dfy-codec --example encode -- --frames 60` → 输出 H.264 Annex-B 文件，可用 ffprobe 校验 1080p 帧数。
4. **端到端（手动）**：两台 Win 机器（或同机双进程）跑 `dfy agent` + `dfy client`：
   - 主控窗口出现被控桌面，延迟 < 60ms（局域网）；
   - 鼠标键盘可用，输入法中文可上屏；
   - 复制文本一侧 → 另一侧 1s 内可粘贴；
   - 拖一个 100MB 文件 → 完成且 SHA-256 一致；
   - 断网 5s 重连成功，会话不崩。
5. **性能门槛**：1080p60 时编码线程 CPU < 25%（硬编）、端到端延迟 P95 < 80ms、丢包 3% 下画面可用（FEC 生效）。

## 3. 里程碑 → 验收映射

- **M0（当前）**：协议规范 + Rust 骨架 + QUIC selftest + 采集 crate。→ 验收 1、2。
- **M1**：编码 + 传输管线 + 渲染窗口 + 输入注入 + 剪贴板文本 + 文件基础版。→ 验收 3、4（部分）、5。
- **M1.5**：码率自适应 + FEC + 统计面板 + 断线重连。→ 验收 4（重连）、5（丢包）。
- **M2**：NAT 打洞 + relay + 临时码/设备配对 + 安全加固。
- **M3**：mac/Linux 被控、Android 主控。
- **M4**：虚拟屏、音频、多屏、高刷。
- **M5**：签名/公证、发布、协议定稿。

## 4. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Win 驱动签名（虚拟屏/HID） | MVP 不做驱动；虚拟屏用"已有物理屏"方案；M4 再上 EV 证书 |
| 编码器差异（NVENC/AMF/QSV/软编） | 编码器工厂 + 能力探测；先 OpenH264 软编保底 |
| 硬件解码渲染（D3D11/零拷贝） | 先 CPU 解码 + 纹理上传，M1.5 再零拷贝 |
| mac TCC/私有 API | M3 才做；提前文档化 |
| Android 上架 | 侧载 APK 先行；Play 版本受限功能 |
