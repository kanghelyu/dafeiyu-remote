## 0. 定位（一句话）
**开源、跨平台、支持自建中继集群的高性能远程桌面系统**——不只是远程控制软件。

## 1. Mission
- 生产级、完全开源、跨平台（Win/Linux/macOS/Android）远控与远程桌面。
- 功能对标 UU 远程；架构/扩展性/组网灵活性/自托管体验要更好。
- 交付整个生态：桌面主控、桌面被控、Android 端、Linux 中继服务器、跨平台网络与通信基建、安装/配置/部署/升级系统。
- 发布到 GitHub，选合适开源许可证。

## 2. 研究与竞品分析（持续维护，官方确认见 docs/research/）
- 合法手段：公开文档/演示、可观察行为、授权互操作测试、公开技术资料、开源实现。
- 研究 RustDesk、Sunshine/Moonlight、Apache Guacamole、NoMachine 等；不盲抄。
- 尊重 IP/许可证/法律；不提取私有源码、不绕过认证、不分发专有组件。
- 产出**功能对比矩阵**（20 类：串流/虚拟屏/多屏/刷新率/键鼠/跨平台快捷键/剪贴板/文件/音频/多会话/重启重连/无人值守/设备管理/质量自适应/NAT 穿透/P2P/中继/安全/安卓控制/会话权限）。
- 全程维护功能实现矩阵；**未测试的功能不得标完成**。

## 4. 核心远控功能

### 4.1 虚拟屏（最高优先级，独立核心模块）
- 无物理显示器也能创建虚拟屏；多虚拟屏；动态改分辨率/刷新率；1080p/1440p/4K；横竖屏；创建/销毁管理；无头运行；物理屏断开仍可远控；独立显示会话；驱动故障后可靠恢复；尽量不改物理显示器设置。
- Win：IDD（Indirect Display Driver）；Linux：DRM/KMS、VKMS、Wayland 虚拟输出、X11 虚拟显示；macOS：受支持虚拟显示 API + 系统扩展（守 TCC）；Android：MediaProjection 截屏 + 授权与后台限制。
- 统一跨平台虚拟屏管理接口。

### 4.2 键鼠与输入翻译层
键盘/鼠标移动/按键/滚轮/组合键/功能键/多媒体键/国际键盘布局/IME 非英文输入/两端不同布局/修饰键翻译。
- 重点：Ctrl↔Command、Alt↔Option、Win↔Super、Ctrl+C/V、Ctrl+Alt+Del、mac Command 组合、Linux DE 组合、特殊键。
- 可配置键盘映射：创建/修改/**导出/导入**；防卡键、断线后正确释放修饰键。

### 4.3 剪贴板同步
文本/Unicode/富文本（可行时）/图片/文件引用（可行时）/大内容/跨 OS 同步。
- 可配置方向、自动/手动、冲突处理、大小限制、安全限制、清晰提示。
- **每个连接独立配置**；**绝不在未授权时静默传输敏感剪贴板内容**。

### 4.4 串流与性能
硬编硬解、H.264、H.265、AV1（支持时）、自适应码率、动态分辨率、帧率自适应、拥塞控制、低延迟传输、区域更新、高效采集。
- 性能档位：低延迟/均衡/高质量/低带宽。
- 统计显示：RTT、丢包、码率、帧率、分辨率、编解码延迟、传输模式、当前中继服务器。

## 5. 网络架构（三模式）
- **A 直连 P2P**：STUN、ICE、UDP 打洞、QUIC 等，优先直连。
- **B 自动中继回退**：P2P 失败或质量不可接受 → 自动切中继，用户无感，尽量不断会。
- **C 用户自选中继**：中继地址不得硬编码；用户可配任意服务器（核心差异化）。

## 6. 中继服务器系统（独立 Linux 程序）
- Linux x86_64 起，ARM64 可行时；单二进制；Docker；配置简单；开机自启；systemd；TLS；安全鉴权；连接管理；并发会话；带宽/资源监控；结构化日志；健康检查；优雅关闭；自动重启；限流；防滥用。
- **只转发加密流量**，不得接触桌面内容或明文会话数据。

### 6.1 极简部署（体验关键）
正常流程 5 步：拿 Linux 服务器 → 跑一条安装命令 → 配置服务器地址与鉴权密钥 → 启服务 → 客户端添加服务器。
- 提供：一键安装、交互式向导、自动生成配置、自动 TLS 证书（可行时）、防火墙/端口诊断、安装校验、一键升级、一键卸载。
- Docker Compose 备选；文档写清端口/协议/防火墙/资源需求。
- 不暴露管理接口或管理凭据。

### 6.2 多中继服务器
客户端可加**无限**中继档案：显示名/地址/端口/鉴权/TLS 配置/区域/优先级/健康状态；支持增删改、连通性测试、手动切换、自动选择、首选服务器、导入导出；UI 明确显示当前使用哪台；不强制官方集中服务器。

### 6.3 选择与故障转移
按延迟/丢包/带宽/地理位置/可用性/用户偏好选择；策略：手动/最低延迟/首选优先/自动故障转移；失败换下一台；切换中保持安全会话、不暴露凭据；可扩展为分布式中继基础设施。

## 7. Android（一等公民）
查看桌面、触摸输入、鼠标模拟、外接键盘、剪贴板、文件传输、虚拟键盘、横竖屏、自适应分辨率、连接管理、中继选择、会话安全。
- 调研后台执行/截屏/无障碍/输入注入限制；明确哪些需用户显式授权；**OS 不允许的能力不承诺**。

## 8. 安全架构（从第一天设计）

- 中继不得解密会话；密码/密钥不明文存储；提供撤销信任设备/终止会话；发布前做安全测试。

## 9. UI（对标商业产品，不要开发者风）

- 连接界面：全屏、多屏切换、分辨率选择、显示管理、键盘映射、剪贴板控制、文件传输、音频控制、画质设置、连接统计、重连、会话权限。

## 16. 最终目标
真正有用的远控生态：优秀虚拟屏、可靠跨平台键映射、无缝双向剪贴板、流畅串流、可靠 P2P+透明中继回退、任意自建中继、极简中继部署、Win/Linux/mac/Android 原生、强安全、打磨的体验、完整开源。
- 中继体系要特别易部署易用：用户不必成为网络专家。
- 超越对标：技术上更好、更灵活、更易部署、更开放。

## 17. 业主亲笔三决策（最高优先级）
1) **中继不是简单流量转发**：P2P 优先 → 质量检测（延迟/丢包/带宽/稳定性）→ 质量合格保持 P2P → 不合格/失败 Relay 接管 → 用户配置的中继服务器池（多服务器、健康检测、自动切换、优先级）。**P2P↔Relay 切换必须是可恢复的会话迁移，而不是断开重连**。
2) **虚拟屏必须独立核心模块**：无头开机后建虚拟桌面、多虚拟屏独立控制、远程改分辨率不影响物理屏、跨 OS 统一抽象、驱动异常自动恢复。Win/Linux/mac 机制差异大，不指望一个通用 API。
3) **中继两种使用模式**：个人自建（VPS + 一键脚本 + 客户端填地址和密钥）优先；多服务器管理（任意数量，自动测延迟选最优，可手动指定），未来可发展独立中继基础设施生态。
- 落地顺序建议：**先 Win/Linux 完整远控链路 + Linux 中继跑通**，再扩 macOS/Android（虚拟屏、输入注入、系统权限都需原生开发）。
